# 整库插画与神明比例验收

2026-10-24。用户明确授权使用原 API 补齐整库，要求补图前先量尺寸，并修正神明显示比例。

## 先测量，再生成

六种屏幕逐一测量后，确认原问题：1280×720 下神明框约 198×74（2.67:1），原图 191×181，`cover` 裁掉了大量人物；手机框却接近方形，断点间比例不一致。

在补图前统一卡面与详情为 16:9，使用 `contain` 完整展示。然后按同一比例生成素材，不从整张 UI 参考图抠出不同尺寸的局部。

| 屏幕 | 神明插画框 | 详情插画框 |
| --- | --- | --- |
| 1280×720 | 199×112 | 320×180 |
| 1536×1024 | 248×139 | 320×180 |
| 1024×768 | 160×90 | 320×180 |
| 768×900 | 85×48 | 320×180 |
| 390×844 | 141×79 | 308×173 |
| 320×740 | 112×63 | 238×134 |

以上为最终浏览器实测尺寸四舍五入值。全部卡面与详情的实际宽高比均为 16:9；卡牌尺寸随货架布局缩放，主体不裁切或拉伸。

## 素材

- 56 张：12 神明、32 技能、12 场地，商品 ID 无漏项或多项。
- 网页素材均为 512×288 WebP，合计 2,228,300 字节，按需加载。
- 神明首批图的头饰过于贴边，重新生成完整坐像，保留头饰、双手、法器与周围边距。
- 五福临门、七星高照、八仙过海单独重新生成，逐一数清五、七、八颗骰子。
- 源图、提示词、视觉描述、切分清单、纠正映射和四张联系表保留在 `output/imagegen/2026-10-24-full-shop/`。
- `scripts/build-shop-art.py` 可重建素材；全部图集及纠正源在首次写入前检查，错误纠正源不会覆盖现有素材。

调用模式为 imagegen CLI，服务为用户指定的 `api.openai-next.com/v1`，模型 `gpt-image-2`。密钥仅在运行时从用户指定文件读取。

## 验证

```sh
/opt/homebrew/bin/node node_modules/vite/bin/vite.js build
/opt/homebrew/bin/node node_modules/vitest/vitest.mjs run --testTimeout=30000
python3 scripts/build-shop-art.py
```

构建成功，90 项现有测试通过，素材重建成功。独立审查指出的“纠正源校验晚于首次写入”已修正并复核；通过隔离临时目录验证，纠正图比例错误时抛错，原素材字节保持不变。

浏览器验证全部 56 张图片加载，六种屏幕无页面横向溢出；桌面与平板的八张价格签及离店入口可见。扩大后的详情图曾遮挡窄屏关闭按钮，现通过顶部留白修正，六种尺寸均实际点击关闭通过。

真实交互覆盖三类商品购买、扣款、售罄、场地布置、刷新后八张新货架全部有图、余额不足禁用，以及正式游戏掷骰、确认、机器人轮转、随机商店和离店进入第二轮。页面和控制台错误均为 0。

已运行 develop-web-game 的标准 Playwright 客户端并查看实际截图。临时验收脚本已删除，数据保留在 [full-shop-art-result.json](full-shop-art-result.json)。
