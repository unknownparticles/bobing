# 博饼 · 今晚谁是状元

![红釉金纹骰碗与六颗跃起的骰子](output/imagegen/2026-10-24-cover/bobing-cover-web.webp)

六颗骰子，和同事们围坐一桌争状元。使用 React 和 Vite 构建，支持电脑和手机浏览器。

在线游玩：[unknownparticles.github.io/bobing](https://unknownparticles.github.io/bobing/)

## 游戏模式

| 模式 | 人数 | 结束与晋级 |
| --- | --- | --- |
| 故事模式 | 组内 6 人 → 部门 8 人 → 公司王中王 10 人 | 每章 8 轮，第一名晋级；未夺冠可重试，晋级时重置局内资源 |
| 快速模式 | 玩家对战 1 名电脑 | 双人完成 8 轮后结算 |
| 经典模式 | 自定义 2～10 人，其余席位为电脑 | 不限回合，最后一份奖品领取后立即结算 |

三种模式均保留卡牌、轮间商店和主角技能。按奖项积分排名，同分比较最高状元等级，仍相同则并列；故事模式并列第一也可晋级。三章包含各自的开场剧情、失败重试和夺冠结局。

商店只购买，不选择攻击对象。雷公、太岁在每轮所有人行动前于桌上选定本轮目标，下轮可重新选人；月老首次上场选人后保持关系至供奉到期。其他神明在场上按各自条件自动触发，技能卡按掷骰前或看结果后的时机使用。

## 随机来牌与自由组合

入席不选择卡组或流派。商店从已解锁的牌池随机发牌，能力来自实际买到的卡牌和供奉的神明；玩家可在对局中发现配合，随时尝试新的组合。

运气成长、夺奖、换位、公开预告和蓄势牌可自由搭配。桌面只显示当前真实效果、连续未获奖次数、座位与公开倒计时；连续失败本身不会自动获得保底，需使用满足条件的卡牌。所有人开局只有一张通用重掷券，故事对手独立的职业能力仍按章节展示。

请神符（40金币）可在掷骰前手选对手的一位正面神明请到自己身上，保留原期限；月老不可请，供奉满三位或已有同名神明时不可请，沿用关帝、反弹和替身防御。送神符（10金币）可解除自己手选的一项神明负面效果，对手供奉保留，下轮仍可发动。

首页“图鉴 · 成就”和对局顶部的图鉴按钮均可查询卡牌、技能与角色。本人货架、获得的卡牌和任何玩家公开使用的卡牌都会收录；入桌角色及其主角、职业技能跨对局保留，章节职业数值按实际阶段区分。“已使用”仅统计本人使用，成就不会因为对手出招而达成。点击桌边玩家可查看当前奖项总份数、各奖项明细、积分和公开效果，奖项转移后实时更新；对手未使用的手牌、数量和尚未生效的供奉不展示。长期档案保存在当前浏览器，兼容原有收集、成就、称号与周目；不会恢复刷新前尚未结束的对局。

## 红釉金纹 3D 骰碗

首页与对局共用 Three.js 绘制的红釉金纹碗和六面立体骰子，支持四至八颗骰子、单骰重投与改点。几何和纹理在本地生成，点数仍由游戏规则提供。

首页的骰碗可以直接玩：点击碗身或摇一摇手机都会完整摇一次碗，骰子逐颗落定，并按对局同一套规则当场判奖（一秀、三红、对堂、状元等）；iOS 首次点击碗身时会顺带申请动作权限，拒绝后仍可点击博饼。

3D 场景独立加载，静止时停止逐帧绘制；遵循系统的减少动态效果设置。设备不支持 WebGL 或图形上下文丢失时，自动显示红金静态碗和可读骰点，仍可正常游戏。

## 安装与离线使用（PWA）

生产构建支持安装到桌面，以独立窗口运行。Android / 桌面 Chrome 或 Edge 可从浏览器菜单选择“安装应用”；iPhone / iPad 使用 Safari 的“分享 → 添加到主屏幕”。

首次联网打开后，请等待应用资源缓存完成，再断网使用。页面、角色和商店图片会一起缓存，之后可离线打开并游玩。关闭或刷新页面会重新回到首页；图鉴、成就和解锁等长期档案保留，当前对局不恢复。

新版本会在联网访问时下载，关闭所有应用窗口和该站点标签页后，再打开即启用，不会强制刷新正在进行的对局。系统清理网站数据后，需要重新联网缓存。

PWA 需要 HTTPS（本地 `localhost` 也可）。开发服务器不注册 Service Worker，验证安装和离线功能请运行 `npm run build` 后执行 `npm run preview`。清单、缓存清单和注册脚本由 `vite-plugin-pwa` 自动生成，兼容 GitHub Pages 的 `/bobing/` 子目录。

图标沿用 `public/icons/bobing-mark.svg`，包含 192 / 512 像素 PNG、带安全留白的 Android 自适应图标及 180 像素 Apple 触摸图标。

## 网页图标与分享封面

已提供 SVG、16/32 像素 PNG 及多尺寸 `favicon.ico`；链接分享封面为 `public/social/bobing-share.png`（1200×630 插画），与 README 顶部横幅同属一批生成图。`index.html` 包含 Open Graph 和 Twitter 分享标题、描述及图片信息。

横幅与分享封面由 imagegen CLI（`gpt-image-2`）生成，提示词与原图保存在 `output/imagegen/2026-10-24-cover/`；封面不再由脚本合成，重新运行图标脚本不会覆盖它。

使用 Python 3 和 Pillow 可从现有 512 像素骰碗图标重新生成兼容图标：

```sh
python3 scripts/build-web-assets.py
```

静态产物随项目一起保存，运行和构建网站无需 Python。

网页图标路径兼容部署子目录。分享元数据的绝对地址使用当前线上站点 `https://unknownparticles.github.io/bobing/`；更换域名或部署目录时，同步修改 `index.html` 的 canonical、`og:url`、`og:image` 和 `twitter:image`。资源用途清单见 `public/icons/README.md`。

## 图片资源

正式角色原图保存在 `public/art/official/`。更新原图后，使用 Python 3 和 Pillow 重新生成 384、768 像素宽的 WebP 与尺寸清单：

```sh
python3 scripts/generate-artwork.py
```

生成文件位于 `public/art/responsive/`，清单位于 `src/art-variants.json`，需要一起纳入版本管理。Pillow 仅用于生成图片，运行和构建网站无需 Python。生成图片的文件名带内容摘要，图片变化时地址随之变化。

`src/Art.jsx` 统一处理部署目录、响应式候选和异步解码。角色主图优先加载，角色选项按可见性加载；头像根据 CSS 放大后的宽度选图，同一角色在不同页面可复用浏览器缓存。修改图片布局时应同步调整 `sizes`，避免下载过大的图片或影响清晰度。

## 发布

推送到 `main` 分支后，GitHub Actions 会运行测试、构建静态网站并发布到 GitHub Pages。
首次发布需在仓库的 **Settings → Pages → Source** 中选择 **GitHub Actions**。
构建资源采用相对路径，支持 GitHub Pages 的 `/bobing/` 子目录。
